2.1 Arquitetura e código

Base de rastreabilidade e sustentação da solução.

Código está versionado no Git padrão da CotripalBloqueante
Solução roda sobre o banco de dados padrão homologado pela TIBloqueante
Existe pipeline de CI/CD ou processo manual documentado de deploy
Ambiente segue padrão de nomenclatura e organização de infraestrutura
Há documentação mínima de arquitetura (diagrama de componentes, fluxo de dados)
Dependências (bibliotecas, SDKs, APIs de terceiros) listadas e com licenças verificadas

2.2 Integração

Evita duplicação de cadastro e dessincronia com sistemas de origem.

Integração com ERP (se houver) é via API documentada e homologadaBloqueante
Integração com base de usuários/colaboradores via diretório central (AD/SSO)Bloqueante
Integração com base de fornecedores/produtores segue o mesmo padrão
Não há duplicação de cadastro que gere dessincronia com sistemas de origem

2.3 Segurança (OWASP Top 10 for LLM Applications)

Requisitos específicos para sistemas que envolvem modelos de IA/LLM.

Prompt Injection: entradas de usuário não alteram instruções do sistema nem extraem dados de outros usuáriosBloqueante
Insecure Output Handling: saída do modelo é tratada como não confiável antes de ser usada
Dados da Cotripal não são enviados a provedores de IA sem contrato/DPA de não-treinamento e retenção controladaBloqueante
Autenticação e autorização seguem o padrão da empresa, não login próprio da ferramenta
Fornecedor de IA tem postura de segurança verificável (certificações, política de dados pública)
Existe registro (log) de quem usou, quando e o que foi solicitado/gerado

2.4 Dados e privacidade (LGPD)

Base legal para tratamento de dado pessoal está identificada, se houverBloqueante
Dado sensível (se houver) tem justificativa e salvaguarda documentadas
Dados não saem do país/região sem avaliação de transferência internacional
Existe processo para atender direito de titular (acesso, exclusão), se aplicável

2.5 Continuidade e operação

Backup e recuperação de dados definidos, se a solução armazenar dado relevante
Responsável técnico definido para sustentação
Plano de rollback ou descontinuação, se a iniciativa falhar em produção

3.1 Enquadramento e risco

Classificação de risco do intake confere com a análise técnica do núcleoBloqueante
Impacto em caso de falha foi dimensionado (estabelecimentos, processo, reversibilidade)
Stakeholders afetados foram identificados

3.2 Aderência estratégica e priorização

A iniciativa resolve problema real da área, com dono definido
Custo (implantação + recorrência) é compatível com o benefício esperado
Não há sobreposição com outra iniciativa já aprovada ou em curso

3.3 Conformidade e responsabilização

Se dado sensível/financeiro: Auditoria e/ou Jurídico convocados e com parecer emitidoBloqueante
Responsável de negócio pela iniciativa está formalmente identificado
Iniciativa está alinhada à Política de Uso de IA da Cotripal
